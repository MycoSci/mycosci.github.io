# MycoSci

Open-source mycology project: free, community-built. Goal is a complete catalog of fungal species (we have ~80–100k taxa resolved as raw data), a deep-search interface, an Instagram-style visual discovery feed (MycoGram), cultivation and lab teks, and educational data-sci visualizations of fungal genetics — gene maps, process maps, senescence/drift over generations.

Live: https://mycosci.github.io/ — deployed via GitHub Pages (custom domain `mycosci.com` not yet wired).

This document is the working source of truth for the repo as it actually is, not as it was once planned. Keep it honest. When something here drifts from reality, fix it.

## 1. State of the repo (2026-05)

The data-driven rebuild described in older versions of this doc is **done**. The catalog is now a single data object rendered to static pages, each with a JSON twin.

What actually exists:

- **Frontend:** Astro 5.6.1, MDX, Tailwind 3. No Starlight (the import path `@astrojs/starlight/components` is aliased in `astro.config.mjs` to local shims in `src/components/docs/`). No React, no D3, no TensorFlow.js. Design language is a restrained "instrument-grade / aerospace" dark theme (see `src/styles/global.css`, `tailwind.config.mjs`) — no neon/glow/noise.
- **Canonical data:** `data/species.json` — **one record per taxon, ~24,431 unique taxa** (21,599 fully resolved + 2,832 flagged `unresolved`), built by `scripts/build-data.mjs` from `data/taxonomy.csv` (74k rows) + `data/species.csv` (curated overlay). `data/species.xlsx` is **corrupt/redundant — ignored**. Per-species enrichment lands as partials in `data/curated/*.json`, merged in at build time.
- **Static JSON API** (generated by `scripts/build-api.mjs` into gitignored `public/`, served as-is): `/species/{slug}.json` (every taxon), `/api/species/{shard}.json` + `/api/species/index.json`, `/api/search-index.json`.
- **Species rendering:** `src/pages/species/[slug].astro` pre-renders **all** taxa from `data/species.json` (HTML + the `.json` twin). The full build (~24k pages) takes ~20–25s, so tiering is unnecessary at this scale — see §3. The 4 hand-written profiles under `src/content/docs/Taxonomy/` are pulled in by `mdxPath`.
- **Search:** client-side over `/api/search-index.json` on `src/pages/database/index.astro` (name/common/family/synonym + phylum filter).
- **Routes:** `index`, `database` (catalog + search), `species/[slug]`, `api`, `docs` (Teks hub), `blog` (static MDX), `detect` / `account` / `gene-bank` (honest "Planned"/"no accounts" pages), `about`, `404`. **No `shop`/`cart` — commerce was removed.**
- **Data model spec:** `docs/SPECIES-DATA-MODEL.md` + `schema/` — the full 244-field target model (14 groups, tiered core/standard/deep, controlled vocabularies, safety policy). Phase-1 subset is wired via `src/lib/species.ts`.
- **Deploy:** `.github/workflows/astro.yml` builds and deploys `dist/` to GitHub Pages on push to `main` (node 20, `npm ci`). Live: **https://mycosci.github.io/** (custom domain `mycosci.com` not yet wired).
- **`ai/`** — scaffolding only, no model (intended MobileNetV3 plan in its README).

There is **no WordPress** — `src/lib/wordpress.ts`, the `wordpress/` docker dir, and the graphql deps were removed. There is no mock data (`src/data/` deleted).

## 2. Mission and scope

Pillars, in priority order:

1. **Catalog.** Every fungal species with a stable URL, taxonomy, and as much sourced detail as we can verify. Scale target: 80k+ taxa. Quality varies by stub depth — aim for "accurate skeleton everywhere, deep where we have data."
2. **Deep search.** Faceted lookup across taxonomy, morphology, ecology, edibility, distribution, genetic markers. Should work on a static build at this scale (prebuilt index, client-side search).
3. **MycoGram.** Visual-first discovery feed — image grid, infinite scroll, links into the catalog. Static-first; user uploads come later if/when there's a backend.
4. **Cultivation & lab teks.** Clear, opinionated guides: agar, LC, grain, fruiting, contamination ID, sterile technique. Process diagrams beat prose.
5. **Gene science education.** Visualize and explain ITS/LSU markers, phylogeny, why cultures senesce, why isolates drift across generations, how to manage gene banks. This is the differentiator — most mycology sites don't go here.

Non-goals (right now): payments, subscriptions, user accounts, mobile apps. The old CLAUDE.md described a WooCommerce/Stripe/gene-storage SaaS — the shop/cart/WordPress code for it has been **removed**, not just deprioritized. Don't reintroduce it unless asked.

## 3. Framework: Astro (static), render strategy as built

**Stay on Astro.** GitHub Pages is static-only; the alternatives don't beat it enough to justify a port.

How rendering actually works now:

1. **A species is data, not a document.** `data/species.json` is the source; `src/pages/species/[slug].astro` renders one static HTML page per taxon plus a co-located `.json` (the per-species API). Editorial content (teks, blog, guides) stays as MDX in `src/content/docs/`.
2. **We pre-render everything.** The earlier worry about 80–100k pages blowing the build does **not** bite at the current ~24k taxa — the whole build is ~20–25s. So there is **no client-rendered long-tail tier**; don't build one until the catalog approaches ~80–100k AND build time actually becomes a problem (re-measure first). The `tier: 'curated' | 'stub'` flag still exists, but it drives *content depth* (curated taxa get a hand-written MDX body via `mdxPath` and richer override data), **not** whether a page is pre-rendered.
3. **Data + API are generated, not committed.** `npm run build` runs a prebuild (`npm run data` → `scripts/build-data.mjs` then `scripts/build-api.mjs`) that writes `data/species.json` and the sharded JSON API into gitignored `public/`. Search index is built the same way and served as a static asset.
4. **Enrichment is additive.** Drop a partial `data/curated/{slug}.json`; the data build merges it over the CSV-derived record, promotes the taxon to `curated`, records provenance, and enforces safety invariants (e.g. reciprocal `dangerousLookalikes`). No CSV edits, no schema churn.

Net effect: build time scales with catalog size but stays cheap at this scale; enrichment scales by adding override files.

## 4. Dev commands

```bash
npm install        # install deps
npm run dev        # dev server at http://localhost:4321
npm run data       # regenerate data/species.json + the static JSON API (runs automatically as prebuild)
npm run build      # static build to dist/ (runs `npm run data` first)
npm run preview    # preview built dist/
```

Node 20. No test suite yet. CI runs `npm ci && npm run build`. Note: `npm run dev` does **not** run the prebuild, so `data/species.json` must exist (it's committed) for the species route to resolve.

## 6. Content model

### Species records — `data/species.json` (the catalog)

Species are **data**, not MDX. Each record's shape lives in `src/lib/species.ts` (the phase-1 subset) and the full target model in `docs/SPECIES-DATA-MODEL.md` + `schema/`. Core fields: `slug`, `accepted` (binomial), the six ranks, `commonName`, `edibility`, `synonyms[]`, `tier`, `sources[]`. Enrichment fields (authorship, registry IDs, vernacular names, ecology, morphology, `dangerousLookalikes`, …) are optional and added via `data/curated/{slug}.json` overrides.

**To enrich a species:** add/edit `data/curated/{slug}.json` (a partial record), then `npm run data`. Don't hand-edit `data/species.json` (it's generated). Safety rules are enforced in `scripts/build-data.mjs` and `src/lib/species.ts`: edibility defaults to `unknown` → rendered "treat as inedible"; never auto-classify edible; `dangerousLookalikes` are made reciprocal at build time; never fabricate registry IDs / accessions (omit them).

### Editorial docs — `src/content/docs/` (MDX/MD collection)

Teks, guides, and blog posts. Frontmatter schema in `src/content.config.ts` (title required; description/author/pubDate/tags optional). The collection globs `**/*.{md,mdx}`. The 4 hand-written species profiles under `Taxonomy/…` are the exception — their bodies are pulled into the species route via each record's `mdxPath`.

### Doc components

Use the local shims from `src/components/docs/` (re-exported via the `@astrojs/starlight/components` alias). Available: `Card`, `CardGrid`, `Tabs`, `TabItem`, `Badge`, `Aside`, `Steps`, `LinkButton`, `Icon`, `TaxonomyChildren`. Don't add new Starlight imports without updating the shim — it's not a real dependency.

## 7. Active workstreams

Done: data layer, species route + JSON API, client-side search, MDX cleanup, frontend, data-model spec, phase-1 enrichment pipeline. Live threads, roughly in order:

1. **Bulk-enrich from open APIs.** Generate `data/curated/*.json` across the catalog from GBIF / Index Fungorum / MycoBank: authorship, year, registry IDs, vernacular names, trophic mode, distribution. Real sourced data only — no fabrication.
2. **Deep profiles** for high-value species (common edibles, toxic, cultivated, psychoactive) — promote to curated with sourced morphology/ecology/cultivation. Cultivation params (humidity/temp/CO2/FAE ranges) are a marquee feature.
3. **Expand the rendered schema** beyond phase-1 as data fills in (microscopy, chemistry, genetics) — extend `src/lib/species.ts` + the species page, guided by `docs/SPECIES-DATA-MODEL.md` (heed its over-engineering review).
4. **Teks** — write the core cultivation/lab guides as MDX under `src/content/docs/`.
5. **MycoGram MVP** — image grid from a static manifest. Source images legally (iNaturalist research-grade, GBIF, CC-BY). Don't ship without attribution metadata.
6. **Gene-science explainers** — phylogeny, senescence, drift. Writing first, visualizations later.
7. **Custom domain** — wire `mycosci.com` (CNAME file + Pages settings + DNS).

## 8. Contribution guide

- Build must pass: `npm run build` is the gate.
- Don't edit `dist/` or `node_modules/`.
- Commits: short `type: description`. Examples in `git log`.
- Species edits: enrich via `data/curated/{slug}.json` then `npm run data` — don't hand-edit the generated `data/species.json`, and don't recreate per-species MDX.
- New routes go under `src/pages/`. New shared UI under `src/components/`. Logic that touches data goes in `src/lib/`. Data/API generation goes in `scripts/`.
- Don't import from `@astrojs/starlight/*` outside of `components/` paths that exist in our shim — it'll break the build.
- This is volunteer/community work. Kindness over correctness in PR reviews; correctness still required in `main`.

## 9. For AI assistants working in this repo

- The user is the maintainer; treat them as the technical lead.
- Default to **honest minimums** over speculative scaffolding. If a system isn't built (AI model, payments), don't write code that pretends it is — the detect/account/gene-bank pages are honest "Planned"/"no accounts" pages, not fake UIs. Keep them that way.
- When adding/enriching a species, don't generate fake DNA accessions, type localities, registry IDs, or authority citations. Omit fields or use `unknown` rather than fabricate. Real sources: IF (Index Fungorum), MycoBank, GBIF, NCBI.
- To scale content, generate `data/curated/*.json` overrides — **never** recreate per-species MDX (that's what we removed). The catalog renders from `data/species.json`.
- E-commerce/SaaS/WordPress has been removed, not just deprioritized; don't reintroduce it unless asked.
- Edibility/toxicity is a safety-relevant claim. If unsure, mark `unknown` and surface a `caution` Aside. Never auto-classify a species as edible without a verifiable source.
